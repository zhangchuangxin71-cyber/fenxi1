# 第一次主持项目复盘：一套能直接照着走的流程

复盘不是追责会，也不是把会议纪要重新读一遍。它的目标是让团队明确发生了什么、为什么发生，以及下一次要改变哪一个动作。

## 会前只准备三类事实

主持人先收集目标、关键结果和时间线，不急着解释原因。事实材料越短越好，保证每个人看到的是同一组信息。

- 原定目标与实际结果
- 关键节点与变更时间
- 已确认的数据和用户反馈

## 会议先对齐再分析

先用十分钟确认事实，再讨论做得好的地方和需要改进的地方。出现分歧时，把问题记录下来，不在没有证据时争论责任。

> 好的复盘把注意力放在系统和行动上，而不是寻找一个承担全部问题的人。

## 收尾只留下可执行动作

每个改进项都要有负责人、完成时间和可验证结果。动作过多通常意味着没有真正排序，第一轮保留三项以内更容易落实。

## 一周后检查闭环

复盘结束不等于改进完成。一周后用短会检查行动进度，删除已经失效的动作，并把有效做法沉淀进团队清单。
